  • 我们想象debian软件的maintainer都做了什么？

package🎁

  • 软件包发布的过程生命周期：

maintainer

  • 上游作者 fph 发布 bastet 最新版
  • maintainer
    • 编译
      • 不同的 cpu 架构要用不同的二进制文件
    • 打包更新到最新的unstable中
    • 放到debian的服务器上去
    • 过了一段时间进入stable的版本
  • ubuntu从debian的服务器下载stable的版本
  • 然后更新到ubuntu的源
  • 清华源、阿里源同步到本地服务器
  • 最终用户从源上获得最终版的软件

时差问题

  • 比如vim的作者更新到了vim9
  • maintainer放到unstable中
  • 等了好久才能下载到stable中的vim9

  • 稳是真稳
  • 稳得有点过了
  • 玩的时候不用这么稳
    • 最新的vim、python、linux都可以试着编译安装一下
    • 不难
    • 而且很有成就感
  • 不过维护服务器的时候必须得稳

两种方法比较

  • 编译安装
    • 可以获得最新版的软件
    • 可以获得特定版本(tag)的软件
    • 可以获得其他架构的软件(交叉编译)
  • apt 安装
    • 非常方便
    • 也可以下载源码
    • 但是版本是maintainer来控制的
    • 就像命令行版的应用商店
